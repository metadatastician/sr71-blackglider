The two top-priority needs of the previous revision are *discharged*, verified
by running the gates rather than by reading a manifest:

workflow ran any proof gate, the Zig tests, or `just test` — verified by

installing its own toolchain. The gate script treats an absent toolchain as
fatal, so a broken install goes red rather than green-by-skip.

== Needs (priority order, 2026-08-07)

[[NEED-1]]
. *Replace the Coq / Agda / Lean template exemplars with domain content* —
  this is now the largest single overstatement risk in the repo. All three
  compile, all three are gated, and *all three are verbatim RSR template
  stubs*: a toy simply-typed lambda calculus (Coq), list-append length and
  monotonicity records (Agda), a `Result` functor and a bounded natural
  (Lean). Their green says the prover ran; it does not say anything about
  Conway physics, the chart, or the glider. The Idris2 MANIFEST is already
  honest about this for `Types.idr` ("template examples, honest ones"); the
  Coq, Agda and Lean MANIFEST notes say only "compiles", which is true but
  reads as more than it is. Either give each a real obligation from
  PROOF-NEEDS, or move them under an explicitly-labelled `examples/` root that
  no readiness claim may cite. Until then: *three green gates, zero domain
  coverage between them.*

[[NEED-2]]
. *Wire or delete the TLA+ spec* — `StateMachine.tla` is checked by nothing
  (`check-proofs.sh` has no `tlaplus` mode) and models an unrelated generic
  request pipeline. Two honest routes: instantiate it against something real
  in this project and add a TLC mode to the gate (which also means installing
  a TLA+ toolchain and pinning it), or delete the file and drop the TLA+
  row from PROOF-NEEDS. Keeping an unchecked uninstantiated template in
  `verification/proofs/` is exactly the shape that gets miscounted as coverage.

[[NEED-3]]
. *A machine-checked refinement from the Idris2 model to the Rust kernel* —
  there is none. The proofs and the implementation are verified *separately*
  and nothing establishes that they agree. Concretely: the Idris2 ABI modules
  prove properties of a *model* of a C ABI, not of the shipped Zig FFI —
  `grep -rn 'CABICompliant\|StructLayout' --include='*.zig' --include='*.rs' .`
  returns nothing, so no Rust or Zig struct is ever presented to the
  compliance certificate, and the only inhabitant is a fieldless empty struct.
  The same gap holds for `Constitution.idr`, whose own header states it "does
  not claim refinement of the Rust implementation". Smallest useful step:
  generate `StructLayout` values from the actual FFI types so the certificate
  has real inhabitants.

[[NEED-4]]
. *Benchmarks and the readiness suite are unimplemented, and now say so* —
  `just bench` and `just readiness` exit 1 with an explanation instead of
  echoing success. That is the correct state, not the finished state: they
  were dependencies of `test-all`, which therefore printed "safe to merge"
  partly on the strength of two echoes. `test-all` is now `test e2e aspect`
  only. Restore them as dependencies *only* when they do real work — a
  `cargo bench` target over `Life::step`, and an executable CRG assessment.
  Tracked as DEBT T-3.

[[NEED-5]]
. *Enforce `scripts/validate-template.sh`* — it is repaired (exit 0, 5
  warnings) and reachable via `just validate`, but nothing in CI and nothing
  on the golden path (`just test && just quality`) calls it. A validator that
  passes where no one is looking is one commit away from being red where no
  one is looking. Either add it to `just quality` or give it a workflow job.

[[NEED-6]]
. *Pin the prover toolchains in `mise.toml`* — `mise.toml` pins rust, just and
  zig only. `just test` now treats an absent prover as *fatal*, so any of
  idris2 / coq / agda / lean4 going missing or drifting breaks the golden path
  with no pinned version to fall back to. The CI jobs install from distro
  packages and elan, whose versions may differ from the 0.7.0 / 8.20.1 /
  2.6.4.3 / 4.32.2 the MANIFESTs were ground-truthed against. Accepted risk,
  recorded as DEBT CI-3; pinning would retire it.

[[NEED-7]]
. *Mission-specification tests* — still blocked on the frozen mission spec
  (`PROOF-ROADMAP.md` names it the next real step). Once a mission exists, its
  replay certificates become golden-file tests. Unchanged from 2026-08-03.

[[NEED-8]]
. *Fuzz harness* — a `cargo-fuzz` target over `Life::step` input worlds.
  Low priority and unchanged: the 4×4 domain is already exhaustively covered,
  so fuzzing adds value only at larger world sizes.

[[NEED-9]]
. *Reconcile or retire `.gitlab-ci.yml`* — it declares "Primary CI/CD —
  GitLab is the source of truth", but `git remote -v` shows exactly one
  remote, `origin` on GitHub, and the file covers none of the proofs, none of
  Zig, and no `just` recipe. A CI configuration for a forge this repo does not
  push to cannot be the source of truth for anything.
