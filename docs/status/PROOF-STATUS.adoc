= Proof Status — SR-71 BlackGlider

== Summary

Two ledgers are tracked here and must not be conflated:

. *Formal (machine-checked)* — the constitutional companion and the ABI proof
  set, gated by `verification/proofs/<prover>/MANIFEST` and verified by
  `bash scripts/check-proofs.sh <idris2|coq|agda|lean4>`. Separately, the
  *shipped* ABI seam (`src/interface/Abi/`, three modules) is typechecked as a
  package by `idris2 --typecheck abi.ipkg`. The seam is a DIFFERENT artefact
  from the template proofs: it lives in the `Abi.*` namespace, the template
  proofs live in `ABI.*`, and `check-proofs.sh`'s MANIFEST covers only the
  latter. Both are now gated; before 2026-08-07 the seam was gated by nothing.
. *Executable exhaustion (Rust)* — finite-domain proofs by exhaustive check
  (`tests/foundation.rs` C1–C7, `tests/constitutional.rs` C8–C13), verified by
  `cargo test`. These are complete over their stated finite domains (all 512
  local B3/S23 rule configurations; all 65,536 4×4 worlds against an
  independent oracle; a 240-generation Snark reflector trace) but they are
  proofs BY EXHAUSTION over a stated finite domain, NOT formal proofs over
  unbounded domains. See `PROOF-ROADMAP.md` for exactly what each establishes.

== WHAT THE GREEN DOES *NOT* MEAN — read before citing this file

This section is normative. Every claim in it was checked in-tree on
2026-08-07; none of it is inference from a status document.

=== The Coq, Agda and Lean4 modules are TEMPLATE EXEMPLARS

`verification/proofs/coq/TypeSafety.v`, `verification/proofs/agda/Properties.agda`
and `verification/proofs/lean4/ApiTypes.lean` are *verbatim RSR template stubs*.
They compile, they are MANIFEST-gated, and they contain no `Admitted`,
`postulate` or `sorry` — and they prove *nothing whatever about Conway
physics, about this project's public API, or about any BlackGlider type*.

What they actually prove, as shipped:

[cols="1,2,3", options="header"]
|===
| Prover | File | What is really proved

| Coq 8.20.1 | `TypeSafety.v` | Progress/preservation for a *toy* two-type expression language (`TyNat`/`TyBool`, `EConst`/`ETrue`/`EFalse`/`EPlus`/`EEq`). The file's own header says "Replace with your project's type system."
| Agda 2.6.4.3 | `Properties.agda` | `length (xs ++ ys) ≡ length xs + length ys`, plus a `Monotone` record template. Header: "Replace with your project's domain-specific proofs."
| Lean 4.32.2 | `ApiTypes.lean` | Functor laws (`map_id`, `map_comp`) for a generic `ApiResult α`, plus `BoundedNat` invariants. Header: "Template — replace with your project's API types."
|===

Their green is *toolchain and gate evidence only*. It demonstrates that the
prover is installed, that the MANIFEST wiring is honest, and that the module
still compiles. It is not domain verification and must never be reported as
such. The Idris2 MANIFEST is already explicit about the same thing for
`Types.idr` ("template examples, honest ones").

Consequence for the ledger: obligation *TP-2* ("Public API type safety —
exported functions", assigned to `lean4/ApiTypes.lean`) is counted as
*Remaining*, not Done, even though the file is gated and green. The file
compiles; the obligation as written is not discharged.

=== The Idris2 ABI set proves properties of a MODEL of a C ABI

Obligations ABI-1 … ABI-5 are discharged against
`verification/proofs/idris2/ABI/*.idr`. Those modules define their own
`StructField`, `StructLayout`, `FieldAligned`, `AllFieldsInBounds`,
`SafePtr` and `CABICompliant` in the `ABI.*` namespace, and prove theorems
about *those definitions*. They do not prove anything about the shipped Zig
FFI in `src/interface/ffi/`, and nothing connects them to it:

* `grep -rIn 'CABICompliant\|StructLayout\|FieldsAligned\|SafePtr' --include=*.rs --include=*.zig`
  returns *zero* hits outside `target/`. No Rust and no Zig source mentions any
  of these names.
* The only inhabitant of the template `ABI.Compliance.CABICompliant` is
  `emptyStructCompliant : CABICompliant (MkLayout "empty" [] 1 1)` — a
  *fieldless* struct with size 1 and alignment 1. No layout of any real
  BlackGlider or FFI struct is certified.
* The shipped seam `src/interface/Abi/Layout.idr` (namespace `Abi.Layout`)
  independently declares its own `StructLayout` and `CABICompliant` and
  certifies one worked example (`struct { int32_t x; int64_t y; double z; }`,
  size 24, alignment 8). That is a genuine, non-trivial certificate — but it
  is a certificate about an Idris2 *description* of a C struct, hand-written
  to match, not extracted from or checked against the Zig code that crosses
  the boundary.

=== No refinement connects the model to the kernel

There is *no machine-checked refinement* between the Idris2 model and the Rust
implementation, and none between either of them and the Zig FFI. The proofs
and the kernel are verified *separately*; nothing in this repository proves
they agree. Any statement of the form "the Rust kernel is proved correct by
the Idris2 proofs" is false.

The Rust kernel is 613 LOC across `src/*.rs` (tests 357 LOC), is
`#![forbid(unsafe_code)]`, and has zero external dependencies. Its assurance
comes entirely from the executable-exhaustion ledger, not from the formal one.

=== Also unwired or absent

* `verification/proofs/tlaplus/StateMachine.tla` is checked by *no gate*:
  `scripts/check-proofs.sh` accepts only `idris2|lean4|agda|coq`, and neither
  it nor the `Justfile` mentions TLA+ anywhere. The file is an uninstantiated
  template modelling a generic request pipeline, irrelevant to this project,
  and no TLA+ toolchain is installed.
* The presentation/renderer layer and the mission semantics *do not exist*.
  `STATE.a2ml` records 25% complete; `PROOF-ROADMAP.md` names a small, frozen
  mission specification as the next real step.
* `mise.toml` pins rust/just/zig but *not* the four prover toolchains, which
  `just test` now treats as fatal-if-absent.

== Proofs Blocked

*None.* The Idris2 quarantine list in
`verification/proofs/idris2/MANIFEST` is EMPTY, and no MANIFEST for any of the
four provers contains a `quarantine` entry. The five previously-quarantined
Idris2 modules (ABI/Pointers, ABI/Layout, ABI/Platform, ABI/Compliance, Types)
and the previously-quarantined `lean4/ApiTypes.lean` were repaired on
2026-08-04–07 and promoted to `gated`.

The quarantine mechanism itself remains live and is not decorative: a module
listed `quarantine` that *starts* compiling fails the gate, forcing this ledger
to be updated. There is simply nothing in it today.

Root causes of the six repairs, for the record — each was distinct and real:

[cols="1,4", options="header"]
|===
| Module | Root cause

| ABI/Platform.idr | `LTE` undefined (needs `Data.Nat`); then `lteRefl` is absent from idris2 0.7.0
| ABI/Layout.idr | `NonZero` undefined (needs `Data.Nat`); then `SIsNonZero : NonZero (S n)` cannot unify with a non-literal `fieldAlignment f` ("Can't solve constraint between: S ?x and f .fieldAlignment"). Restated as `NonZero` + divisibility
| ABI/Pointers.idr | Proof ACCESSOR declared at runtime quantity instead of `0`; fixed with one character on the accessor (`0 safePtrNeverNull`)
| ABI/Compliance.idr | Downstream of Layout/Platform; `sizeAligned` restated the same way, with the `NonZero` conjunct retained
| Types.idr | An idris2 positivity-checker limitation on a type synonym; `AFBCons` unfolded past it
| lean4/ApiTypes.lean | A binder named `max`, which can never auto-bind as an implicit because `max` is a global function in Lean 4; renamed to `bound` and the `ApiResult` namespace closed
|===

== Verification Commands

Every command below was run in this working tree on 2026-08-07 and produced
the result recorded in the ledgers above.

[source,bash]
----
# The four MANIFEST-driven prover gates.
# An absent toolchain is FATAL by design — a gate that cannot run never reports OK.
# A quarantined module that starts compiling is itself a gate failure.
bash scripts/check-proofs.sh idris2    # 7/7 gated PASS, quarantine empty
bash scripts/check-proofs.sh coq       # 1/1 gated PASS
bash scripts/check-proofs.sh agda      # 1/1 gated PASS
bash scripts/check-proofs.sh lean4     # 1/1 gated PASS

# The SHIPPED ABI seam (src/interface/Abi/, 3 modules) — a separate artefact
# that check-proofs.sh's MANIFEST does NOT cover. Package typecheck, not --check.
idris2 --typecheck abi.ipkg

# The executable foundation (C1-C13), by exhaustion over finite domains
cargo test --all-targets               # 12/12 pass

# The Zig FFI
(cd src/interface/ffi && zig build test --summary all)   # 11/11 tests, 5/5 steps

# SPDX coverage + dangerous-construct scan
bash tests/aspect_tests.sh             # PASS=2 FAIL=0 WARN=0

# The repo golden path — `just test` runs cargo, zig, abi.ipkg and all four
# prover gates; `just quality` re-runs the prover gates plus lint/format
just test && just quality
----

CI: `.github/workflows/proof-gate.yml` (added 2026-08-07) runs one job per
prover, each installing its own toolchain. Before that workflow existed, *no*
workflow in this repository invoked `check-proofs.sh`, `just test`, or the Zig
tests — every proof was enforced on one laptop and nowhere else.
